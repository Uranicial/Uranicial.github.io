Git 和 GitHub 是什么

简单来说，Git 是管理文件修改记录的工具，GitHub 则是我们用来存放、共享这些记录的平台

这里先说明几个后面会用到的概念，不需要各位现在就全部记住

名称 简单理解
本地仓库 你电脑上的项目文件及其修改记录
远程仓库 存放在 GitHub 上的项目仓库
main 主分支，存放经过审核的内容
个人分支（Branch） 各位用来提交自己作业的分支
clone 第一次将远程仓库复制到电脑上
pull 将远程仓库的更新获取并整合到当前分支
add 选中准备提交的修改
commit 在本地保存一次修改记录
push 将本地的提交记录上传至远程仓库
Pull Request（PR） 请求将个人分支中的修改合并进另一个分支
merge 将一个分支的修改合并到另一个分支

对于各位来说，提交一次作业大概就是这么一回事

注意：push 成功并不代表作业已经合并到主分支，后面还需要提 PR

命令中以 # 开头的内容是注释，主要用于解释命令的作用；示例中的报错和运行结果不是让各位输入的命令

等待审核及修改

一般来说，仓库管理员在 Review 后确认无误，会将该PR Approve，并将 PR Merge 进 main 分支

如果个人分支仍然存在，就继续使用原来的个人分支

如果管理员在合并后删除了远程个人分支，先确认之前的作业已合并

再按管理员要求从最新 main 重新建立个人分支不要为每次任务随意创建一堆分支

  3. 本地私钥文件是否还存在

SSH 测试成功了，为什么还是 Repository not found？

SSH 认证成功只说明 GitHub 识别出了你的账号，并不代表你拥有所有仓库的访问权限

确认仓库地址是否正确，登录 GitHub 后能否直接打开任务仓库，以及有没有接受管理员发出的邀请

如果网页也打不开仓库，请先联系管理员，不要反复配置 SSH

已经 Push 了，为什么 main 里还是看不到我的提交？

请先在 GitHub 上切换到自己的分支查看文件是否存在

如果存在，说明 Push 成功了。接下来检查是否已经创建 PR，以及 PR 是否已经被管理员 Merge

再次强调一下，Commit、Push 和 Merge 是三件不同的事

PR 已经创建了，发现作业有问题，还能修改吗？

可以。只要 PR 还处于 Open 状态，在原个人分支上修改并重新 add、commit、push 即可，原 PR 会同步更新

如果已经 Merged，则按新的修改流程发起 PR
